## 2. 核心知识点（用自己的话写，各 2-3 句）

- **检索**：Embedding → Milvus 相似度检索 → Top-K。
  > 答案：首先将用户输入的问题query通过embedding后得到向量，然后在余milvus的数据根据余弦相似度计算出分数，取分数从高到低排名的top-k.
  > ✅ **批阅：概念完全正确。** 两处小修：① 错别字"在余"→"在 Milvus 里"；② 可补充"返回的是 chunk 及其元数据（来源/标题）"，面试追问"你返回什么"时用得上。

- **生成**：Prompt 防幻觉三板斧（角色 / 只答资料 / 不知为不知）+ temperature=0.3。
  > 答案：首先定义大模型的角色，可以让大模型清楚自己要做什么。
  > 严格让大模型根据检索的数据充当上下文来回答问题，防止大模型有幻觉。
  > 没有检索到数据我们让大模型回答没有检索到，这里需要设置一个阈值分数，如果分数过低的话，会给大模型带来幻觉，因此我们将分数低的去掉。
  > ⚠️ **批阅：前两板斧 ✅，第三板斧概念混了。** 你写的"阈值过滤（分数低的去掉）"是**检索侧**的事（第 2 周做 MIN_SCORE 过滤），不属于 Prompt 三板斧。当前 Prompt 里第三板斧是**生成侧**的"不知为不知"——让模型在"资料里有但答不上/资料里没有"时如实说"资料中没有相关内容"，而不是编。两者是**双保险**（检索过滤 + 生成约束），面试要能分开讲。
  > ✅ **参考答案（生成侧三板斧）**：① 角色设定：明确"你是严谨的问答助手"；② 资料约束：只能依据提供的资料回答；③ 兜底约束：资料中没有相关内容时明确回答"资料中没有相关内容"，禁止编造。temperature=0.3 降低随机性，进一步减少幻觉。

- **容错**：可重试（超时/连接/429 限流）vs 不可重试（401/400），退避重试有上限。
  > 答案：401错误属于代码本身有问题，而不是因为网络等其他问题，网络等问题可以通过重试来解决。
  > ⚠️ **批阅：第一问 ✅（意思对，建议措辞改为"401 是鉴权/配置问题，重试不会改变结果"）。第二问没答**：为什么退避要 1s、2s 递增而不是固定 1s？
  > ✅ **参考答案**：固定间隔会让所有失败请求在**同一时刻**集中重试，可能把服务端打崩（重试风暴）；递增退避让重试**错峰**，也给服务端留恢复时间。类比：多人同时敲门，隔 1s 全在敲 vs 逐个错开。

- **单测**：快、稳、隔离三原则；monkeypatch 用假数据替换真实 API。
  > ⚠️ **批阅：两个问题都没答，补一下。**
  > ✅ **参考答案**：单测不能依赖网络因为要"快、稳、隔离"——真 API 又慢又贵还可能失败，CI 上没网就跑不了；monkeypatch 实际替换了 `retriever` 里的 `embed_query` / `_make_client` / `search` 三个函数，用假 hits 验证"我组装 dict 的逻辑对不对"，不碰真实调用。

## 3. 踩过的坑（技术笔记已有 6 条，这里挑最狠的 1 条复述）

> - Milvus 查询前必须先 `load_collection()`（code=101）
> - `.env` 键名 `MILVUS_URI` 与 pymilvus 冲突

**坑：**`user_prompt` 误写成列表 → DeepSeek 400（Day 5 自己踩的）
- **现象**：`BadRequestError 400: messages[1]: invalid type: string ... expected ChatCompletionRequestContentBlock`。
- **根因**：`user_prompt = [f"..."]` 误用**方括号**成了列表 → openai SDK 把 content 序列化成裸字符串数组 `["..."]`，DeepSeek 要求数组元素必须是 `{"type":"text","text":...}` 对象 → 400。
- **解决**：`user_prompt` 改回**字符串**（含 `\n` 分隔的文本）。
- **面试怎么说**："content 要么是字符串、要么是规范内容块数组，不能是裸字符串数组——这种类型坑直接看报错里的 expected 字段就能定位。"
  > ✅ 批阅：这条你已在 day6.md / tech-notes.md 记录过，这里复述一遍作为"最狠的坑"即可，无需再改。
